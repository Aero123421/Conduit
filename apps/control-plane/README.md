# Conduit Cloudflare Control Plane

This app is the single-owner Cloudflare control plane for Conduit's Linux vertical slice. It owns shared collaboration intent and metadata. It does not own canonical Device paths, Device private keys, Agent-provider credentials, process state, VM disks, or raw logs.

## Platform layout

- Worker: versioned `/v1/*` APIs, authentication/consent state, OAuth 2.1 endpoints, bounded Project/Session snapshots, and stateless Streamable HTTP MCP at `/mcp`.
- Workers Static Assets: Setup, Login, Device enrollment, and Dashboard shells and JavaScript. Asset-first routing is mandatory; `run_worker_first` remains unset.
- D1: migrations in `migrations/`, including auth, policy, Device registry, collaboration, operation, artifact, trace-index, and immutable security-event records.
- `DeviceRoom`: one SQLite-backed Durable Object per Device. It persists connection epochs and transport inbox/outbox custody before acknowledgement, uses hibernatable WebSockets, and bulk-projects Free-profile event batches from its durable inbox without Queue operations.
- `BoardRoom`: one SQLite-backed Durable Object per Collaboration Session for bounded live fan-out. D1 remains authoritative for Messages.
- `ConnectorLimiter`: one SQLite-backed Durable Object per OAuth grant for compact weighted/byte budgets and concurrency accounting. Read-only calls do not create durable idempotency rows; D1 operation records remain authority for effectful idempotency.
- `RetryScheduler`: one singleton SQLite-backed Durable Object whose sole alarm tracks the minimum due operation, approval, realtime, or retention retry. Cron is a five-minute crash-gap backstop.
- Queue: optional Standard-profile at-least-once projection. One Node `event.batch` remains one Queue message, valid siblings survive poison isolation, and commits are deduplicated by Conduit event identity and Run sequence.
- R2: explicitly authorized artifact bodies only. D1 commits metadata and upload policy first.

## Local development

From the repository root, use the pnpm workspace so `@conduit/schema` is built and linked before this Worker:

```sh
pnpm install
pnpm --filter @conduit/schema build
pnpm --filter @conduit/control-plane types
pnpm --filter @conduit/control-plane migrate:local
pnpm --filter @conduit/control-plane test
pnpm --filter @conduit/control-plane typecheck
pnpm --filter @conduit/control-plane deploy:check
```

`wrangler.jsonc` contains deployment template names and a non-production D1 ID. Replace the D1 ID and provision the named R2 bucket, Queues, and dead-letter Queue for the target account.

The checked-in deployment defaults to `CLOUDFLARE_USAGE_PROFILE=free`. The Free profile uses DeviceRoom `durable_inbox` event custody, five-minute Cron backstop, 0.20 log sampling, and 0.01 trace sampling. `standard` keeps the same correctness and security contracts while enabling Queue ingestion and different throughput knobs. Unknown profile values fail closed. See `docs/CLOUDFLARE_FREE_TIER_BUDGET.md` for measured counters, explicit quota projections, retention classes, and release assertions.

Run `pnpm --filter @conduit/control-plane deploy:check` before deployment. It verifies the usage profile, Cron schedule, observability sampling, Static Assets binding, and asset-first route behavior. Isolated E2E may deliberately use full sampling; production Free must retain the checked-in defaults.

Set secrets without committing their values:

```sh
wrangler secret put BOOTSTRAP_VERIFIER
wrangler secret put TOKEN_PEPPER
wrangler secret put RECEIPT_SIGNING_KEY
```

`BOOTSTRAP_VERIFIER` is the lowercase SHA-256 verifier of a locally generated 256-bit bootstrap secret. `TOKEN_PEPPER` and `RECEIPT_SIGNING_KEY` must each contain at least 256 bits of independently generated random material. The plaintext bootstrap secret is shown once and never placed in a URL.

The checked-in `worker-configuration.d.ts` is generated by Wrangler. `SecretBindings` augments that generated binding surface only with the three traditional Worker secret names; it does not duplicate configured bindings.

## Retention and public-write protection

Published realtime rows, Board fanout dedupe, transport receipts, health receipts, consumed or expired browser/OAuth records, completed enrollment transactions, effect records, limiter windows/leases, and high-volume streaming deltas are bounded hot data. Cleanup runs in pages and continues only while a backlog exists. Messages, important Assignment/Run transitions, terminal receipts, Approval commitments and decisions, Change Sets, Reviews, Baselines, artifact metadata, and security archive roots remain long-lived. Ordinary cleanup never deletes `security_events`.

Authentication challenge, Dynamic Client Registration, and Device enrollment creation use short TTLs plus global and keyed source caps; raw client IP addresses are never stored. Invalid enrollment polling returns an exponential server-provided `Retry-After`. Deployments with Cloudflare WAF/rate rules should also rate-limit `/oauth/register`, `/api/v1/device-enrollments`, and invalid enrollment polls. Application limits remain active when WAF is unavailable.

## Security boundaries

- Browser cookies are `Secure`, `HttpOnly`, host-only, `SameSite=Lax`, rotated after authentication/step-up, and coupled with exact-origin plus CSRF checks.
- WebAuthn challenges are one-time, RP/origin-bound, user-verifying, and expire after five minutes.
- OAuth uses Authorization Code with PKCE S256, exact redirect matching, MCP resource binding, short access tokens, rotating refresh tokens, and family revocation on reuse.
- Owner CLI tokens use a distinct `conduit_owner_` credential namespace, are issued only after verified passkey login, and are never accepted at `/mcp`; OAuth connector tokens are never treated as owner credentials.
- Recovery sessions are restricted in API middleware and cannot reach project/run APIs or MCP.
- Device enrollment and rotation verify Ed25519 possession; only public keys reach D1.
- Connector authorization intersects OAuth scope, current policy revision, target selectors, Runtime/Access/Approval ceilings, content/upload permissions, durations, and exact budgets.
- Operation intent and idempotency are persisted in D1 before a `DeviceRoom` offer. A transport acknowledgement is never treated as execution completion.

The Worker expects Device-local policy and Runtime capability checks to produce separate admission/start/terminal receipts. A Cloudflare allow decision never overrides a Device-local denial.
